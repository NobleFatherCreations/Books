# Playbook: take one Sacred Divide volume from first pass to finished PDF and TikTok series

Worked example: `protestant-evangelical` (Southern Baptist sector), October 2026. Everything below was done once, by hand, and works; repeat it per volume. IDs are volume ids from `content/sacred-divide/religions/<id>.md`.

## 0. Rules that applied throughout
- No deploys or production writes without explicit go-ahead (CLAUDE.md). Nothing here deploys.
- One background agent at a time by default, at most two staggered. On a 429 stop dispatching, wait for the reset time in the error, resume one agent (canary), then two.
- Commit only finished volumes' files plus shared logs. Never commit a running agent's partial files.
- Every wording change is a reversible entry in `content/sacred-divide/edits/<id>.json` (status `rejected` undoes it). Never hand-edit `content/sacred-divide/religions/<id>.md`; it is regenerated by `scripts/sacred-divide-export-md.py`.

## 1. Language pass and fact-check (per volume)
1. Dispatch one agent with `docs/sacred-divide-v5/AGENT-BRIEF.md` (substitute `{RID}` and `{PFX}`; add: do not move loop text between cards, never soften a factual claim, do not commit, touch only that volume).
2. Deliverables: `edits/<id>.json` (all applied, 0 FAILED in `logs/edits-status.json`), `logs/fact-check/<id>.md`, `docs/sacred-divide-v5/discrepancies/<id>.md` (P1/P2/P3), `docs/sacred-divide-v5/proposals/<id>.md`, `logs/wording-log/<id>.md`.
3. Commit those files plus `content/sacred-divide/religions/<id>.md`; push.
4. Shared help-line corrections go in `content/sacred-divide/edits/_all.json` (ALL-F01 to F06 so far) and are logged in `docs/sacred-divide-v5/DISCREPANCIES.md`.

## 2. Applying the discrepancy list (what "fix every discrepancy" means)
Append `PE-D###`-style entries (use the volume's prefix and `D`) to the volume's edits file, in this order, then re-run `python3 scripts/sacred-divide-export-md.py` and check every entry is `applied`:
1. **Unsourced thesis claims**: add a numbered source at the end of §26 (after the help-line sources), cite it where the claim appears, and name the examples.
2. **Size/figure rows**: rewrite from the source's own figures (check for double counting across volumes).
3. **Regrades**: when a grade's basis does not match its entry, regrade and rewrite the `**Evidence grade.**` line. Remove `*(sourced)*` from any technique that names no document. Then recompute the §1 Evidence row (counts of each grade, number "sourced") so it matches the chips: count with `grep -c "^\*\*Evidence grade.\*\* \[\[Taught\]\]"` etc.
4. **Overstated lines**: soften only where the source does not support the claim, and say what the source does support. Never soften a sourced claim.
5. **Case tags**: change `- **tactics:**` lines where a tag is not supported by the case text.
6. **Layout items** (e.g. a `::: cites` block in the middle of §19): move with a two-string edit.
7. **Narration**: edit `scope: narration` entries. The case-count sentence is generated ("N documented cases on this page …"); when the number of cases changes, update that edit's `before` numeral. The generated sentence over-claims ("court, regulator or inquiry record"); the Protestant volume rewrites it to "court, regulator, inquiry or investigative record" (candidate for a global fix).
8. **Meta**: set `checked:` and the "Last checked" glance row, and add a dated bullet at the top of §27 (patch note).
9. Write `docs/sacred-divide-v5/<id>-FIXLOG.md`: a table mapping every discrepancy item to its edits, plus what was left on purpose and why.
Decision items (house style across volumes, new research proposals) are not "fixes": list them in the fix log.

## 3. PDF (US Letter, EB Garamond)
- Per-volume pull-quotes: `content/sacred-divide/pullquotes/<id>.json` (slug → one verbatim sentence from the volume). Catholicism keeps its own set inside the script. A volume without a file gets no pull-quotes. **Never reuse another volume's quotes** (this leaked Catholic text into other volumes before the fix). Verify each quote occurs in the volume text.
- Build: `python3 scripts/sacred-divide-v5-build.py <id>` (3 layout passes). Output `library/_undeployed/sacred-divide-v5/<id>-expanded.pdf`.
- Check: `python3 scripts/sacred-divide-v5-qa.py <pdf>` (sizes, palette, fonts), then veraPDF (`verapdf --flavour ua1`), which should report `isCompliant="true"`.
- Look at contact sheets of every 24 pages (PyMuPDF at 36-62 dpi). Things that went wrong and the fixes now in place: loops forced `break-inside: avoid` (fixed: float the diagram, let text flow); cover title overlapped the footer on long names (class `long`, 72 pt); Catholic pull-quotes in other volumes (fixed). 50 or so pages are still more than 15% empty at the foot: the full design pass is paused.

## 4. TikTok photo series
- `python3 scripts/sacred-divide-tiktok-build.py <id>` builds `content/sacred-divide/tiktok/<id>.json` from the volume's own Markdown (headings, tables, cards, techniques, loops, cases). It strips citation numbers, receipt labels and section cross-references; it adds nothing.
- `python3 scripts/sacred-divide-tiktok.py <id>` renders 1080×1920 PNGs with Chromium, one folder per post. Text zooms down to fit; any slide that would go below 0.75 of full size is split into two. Posts are split at 35 images (TikTok's limit).
- Safe area: top 160 px, bottom 400 px, right 140 px stay clear. Slide counter is top right inside the safe area.
- Volumes with a different structure (table-format §12, no loops as cards, fewer sections) may need small parser changes in the build script; run it and look for empty slides.
- Review: contact sheets of a dozen slides per post; scan `series.json` for leftover markup (`**`, `###`, `:::`, `[`).
- Package: copy posts to `exports/<short>/tiktok/post-NN/`, add `README-POSTING-ORDER.txt` (caption and hashtags per post), then zip in groups under **30 MB each** (the upload tool's limit): PDF and documents in one zip, posts in 3–4 zips.

## 5. Per-volume checklist
- [ ] language pass committed (1)
- [ ] fix log written, all PE-D-style edits applied (2)
- [ ] pull-quotes file written and verified (3)
- [ ] PDF built, QA clean, veraPDF compliant, contact sheets read (3)
- [ ] TikTok series built, rendered, contact sheets read, scanned for markup (4)
- [ ] zips under 30 MB each, committed (exports/), pushed
- [ ] MEMORY.md updated; sites.json and the on-page §27 entry only when deploying
