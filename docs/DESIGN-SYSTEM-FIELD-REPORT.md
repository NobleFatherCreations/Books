# Design system field report: what happened when it was run start to finish on Fractal² v9 (2026-11-11)

Written by the model that built v9, straight after doing it. Purpose: a concrete list of what to change in the design system, from use, not theory. Ordered by how much each item would have saved.

## What the system did that mattered
1. **The Budget (07 section 2)** forced one concept and one signature move. v9's "one light" came from writing that sentence; v8 had effects but no sentence.
2. **Failure-mode names (F1-F14)** made diagnosis fast. v8's problems were F2 (captions on ring lettering), F7/F8 (one picture for 45% of the scroll). Naming them pointed at the fix (move words off the art; give each caption a figure).
3. **Story lint** caught nothing new this round but let the script be rewritten quickly without fear.
4. **Fixed rubric + exit gate** kept the stop condition honest.

## What it could not do, and the fix for each

| # | Gap found in use | Evidence | Fix (status) |
|---|---|---|---|
| 1 | **Gates were blind past a locked opening.** `design-gates.mjs` and `capture-critic-set.mjs` loaded the page and scrolled, but the page does not scroll until Begin is pressed. The gates reported PASS on 2 screens out of 66. Every v8 "gates pass" was a pass on the opening screen only. | First v9 gate run: "2 screens", 0 FAIL. With the button pressed: 70 screens, 5 FAIL. | DONE: `--click "#begin"` on the gates; a click argument on the critic capture. STILL NEEDED: the gate should FAIL when it sees fewer than 3 screens or when `html` has `overflow:hidden`, so a blind run can never pass again. |
| 2 | **Nothing showed the film as a film.** The system produced single screenshots. Pacing, dead stretches and caption collisions only show in sequence. | v8's static middle is obvious in one contact sheet and invisible in any single frame. | DONE: `scripts/frame-walk.mjs` (+ `frame-sheet.py`): N evenly spaced frames on one sheet, each labelled with scroll %, camera scale and the caption on screen; prints console errors, overflow and the fastest camera move. Make it step 1 of every critique round. |
| 3 | **No motion gate.** A camera target that jumped about 60% of each move at every caption change sat in v8 unnoticed (end markers were placed one screen late, so scenes overlapped in marker order). | Found by reading the marker math, not by any tool. | PARTLY: frame-walk prints "fastest camera move per screen of scroll" when the page exposes `window.__cam()`. NEEDED: sample the target between frames at fine steps and fail on any discontinuity. |
| 4 | **Contrast gate samples mid-fade.** It flagged captions that were 40% through a fade. Real, but indistinguishable from a true contrast failure. | 5 FAILs went to 0 when the dark pool was held through the fade. | NEEDED: report contrast at the caption's full-opacity moment and, separately, "time below contrast during transitions". |
| 5 | **The process is too heavy for a rescue.** PROMPT-MASTER asks for an interview, 10 reference sites, a 56-category coverage sheet, three comps and an owner stop before any real build. For "merge two existing builds and ship" that is hours of ceremony. I skipped: interview, new reference research, COVERAGE refill, three comps, the owner hero stop. I kept: Budget, F-mode critique, frames read, gates, one independent critic, exit gate. | This session. | NEEDED: a written **Rescue track** in the skill: (1) frame-walk both builds, (2) name failures by F-number, (3) one concept sentence + Budget, (4) build, (5) frame-walk + gates + one critic, (6) exit gate. One page, not six documents. |
| 6 | **Emotional payoff has no check.** The rubric has "feeling" but nothing asks whether the ending pays off the opening. v8's ending never returned to the room. | The strongest v9 change (the closing callback) came from reading v1's script, not from any gate. | NEEDED in `story-lint.mjs`: a "callback" rule (an image from the first three scenes must return in the last eight), and in the critic prompt: "what is set up in the first minute, and is it paid off?" |
| 7 | **The catalogue has no figure language section.** It lists styles and effects, but not "how a diagram tells one sentence": one figure per caption, built around a constant element, drawn in the art's coordinates. | v1 had this by instinct; v8 lost it; nothing in the catalogue would have told v8 it was missing. | NEEDED: a short chapter "Explanatory figures in scroll stories" with the v9 cue table (`DESIGN-CHOICES.md`) as the worked example. |
| 8 | **Phone layout rule missing: words and art need their own regions when the art is the subject.** v6 tested a split layout once, scored it the same as overlay, and dropped it. The test was run without figures, so there was nothing for the split to protect. | v9: split from the large map onward removed every text-on-art collision in that section. | NEEDED in 07: "overlay only while the art is texture; split as soon as the art carries meaning". |
| 9 | **Critic variance.** One critic, one run, noisy. | Journey doc notes a score moving with no related change. | NEEDED: the critic prompt must demand a frame file name for every claim (done in this session's prompt; copy it into the template), and scores should be the median of the same critic prompt run twice when a score sits at the threshold. |
| 10 | **No real-device step the model can do.** Every "phone" result here is Chromium at 390x844. iOS Safari (fixed canvas, large images, `svh`, programmatic scroll for Play) is untested. | Unchanged from v8. | NEEDED: the hand-off must always end with a 6-line owner phone check, and the exit gate should print "real phone: NOT TESTED" until a dated line is added to `PHONE-CHECK.md`. |
| 11 | **Documents multiply.** HANDOFF, JOURNEY, STATUS, DESIGN-NOTES, DESIGN-STATE, COVERAGE, SCORES, DESIGN-CHOICES, STORY-DECISION, PHONE-CHECK. A new model spends its first 20 minutes reading. | This session. | NEEDED: one living `DESIGN-STATE.md` per project (state, choices, scores, open items), everything else archived. |

## Order to do them in
1, 5, 2 (make blind passes impossible; add the Rescue track; put the frame walk first), then 6 and 8 (they are where the quality came from), then the rest.
